# Recreate the system in a demonstration environment

This repository provides a **portfolio copy** of the Apps Script source. It is not connected to the client's forms, Sheets, Looker Studio or Google Sites. Only run the scripts against assets you control, after confirming the column and tab names match.

## 1. Create the spreadsheet and work submission form

Create a new Google Spreadsheet. Link a work submission form to it so the response tab is named exactly `Form Responses 1`, or update `SOURCE_TAB` in `src/ReportingSync.gs`.

The source response sheet needs these exact column headings (capitalisation is not important, but spelling and spacing are):

- `Timestamp`
- `Employee name` (single or checkbox response; the script selects the last non-empty same-named column)
- `Date of Work`
- `Work Location/Site`
- `Job type`
- `Job Description`
- `Day Type`, or the legacy question `Were you at the site for full day or half day?`

`Job Record ID` is created by the reporting script if it is missing. `Reporting Data` is created or rewritten automatically. **Do not manually store information in `Reporting Data`: each rebuild clears its content.**

## 2. Create the directory tabs

Create `Employees` and `Sites` sheets. In each, set up these columns:

| Column | Header | Purpose |
| --- | --- | --- |
| A | ID | `EMP001` / `SITE001` style identifiers generated by script |
| B | Name | Employee or site name |
| C | Status | `Active` or `Inactive` |

Set up a colored dropdown/data-validation rule containing `Active` and `Inactive` in cell `G2` on **both** tabs. The script copies that validation to column C when a row has a name. The template itself stays in G2.

## 3. Create and configure Google Forms

Create a Google Form containing:

- A **checkbox** item titled `Employee name` (supports multiple workers on one job).
- A **dropdown** (list) item titled `Work Location/Site`.

Open your new spreadsheet, choose **Extensions > Apps Script**, and add the two `.gs` files from `src/`.

Then in the Apps Script editor, go to **Project Settings > Script properties** and add:

| Property | Value |
| --- | --- |
| `WORKFORCE_FORM_ID` | ID of your **new demonstration** Google Form |

To find the test form ID, inspect the form edit URL. **Do not put real form IDs into the repository or screenshots.** The directory script looks up the ID through `PropertiesService` at runtime.

## 4. Optional registration forms

To use `handleDirectoryFormSubmission(e)`, connect separate employee and site registration forms to the same spreadsheet and make sure their response tabs have these exact names:

| Response tab | Required submitted question |
| --- | --- |
| `New Employee Requests` | `Employee Name` |
| `New Site Requests` | `Site Name` |

The function ignores submissions from other response tabs. For accepted submissions it adds an Active record to `Employees` or `Sites` and synchronises form choices.

## 5. Configure triggers

In the Apps Script editor, open **Triggers** (clock icon), select **Add Trigger**, and create installable triggers appropriate for the test environment.

| Function | Suggested event source and event type | Purpose |
| --- | --- | --- |
| `syncEmployeeDropdown` | From spreadsheet, On edit | Rebuild employee checkbox choices when Employees tab is edited |
| `syncSiteDropdown` | From spreadsheet, On edit | Rebuild site dropdown choices when Sites tab is edited |
| `handleDirectoryFormSubmission` | From spreadsheet, On form submit | Process new employee/site registration requests |
| `rebuildWorkforceReporting` | From spreadsheet, On form submit | Rebuild reporting records when work is submitted |
| `rebuildWorkforceReporting` | Time-driven, periodic (optional) | Reconcile manual changes/deletions that may not be captured by form submission events |

If desired, also create an **On edit** trigger for `rebuildWorkforceReporting` to rebuild after edits in the response tab. This does not guarantee that row deletions will be captured immediately, and Looker Studio may still cache data. Installable triggers need authorisation from a user who has access to the test spreadsheet and form.

Run `syncEmployeeDropdown` and `syncSiteDropdown` manually once in the test project after setting the property and populating Active names (at least one active employee and one active site are required). To repair status dropdowns, run `cleanupEmptyStatusDropdowns` manually with care: it replaces existing validation rules in column C.

## 6. Add the reporting layer

Connect a **new test** Looker Studio report to the `Reporting Data` sheet and use `Date of Work` as the work-date dimension where appropriate. Create employee/site/date filters and relevant scorecards and tables. A single submitted job with two employees is expanded into **two reporting rows sharing one Job Record ID**, so count distinct jobs rather than rows if reporting on distinct submitted jobs.

Optionally make a demo Google Sites hub linking to the test form and dashboard.

## 7. Check the demo before sharing

- Confirm new employees/sites get unique IDs and statuses, and active choices appear in the test form.
- Confirm deactivating a name removes it from future selections without erasing historical work records.
- Confirm a multi-employee form submission produces one reporting row per selected employee with the same Job Record ID.
- Confirm changes to or deletions of source responses appear after a reporting rebuild.
- Confirm date fields are recognised as dates in Looker Studio.
- Confirm no client data, personal information, tokens, real form IDs, restricted URLs or production screenshots are committed.

For command-line Apps Script source control, see Google's `clasp` documentation: https://developers.google.com/apps-script/guides/clasp
